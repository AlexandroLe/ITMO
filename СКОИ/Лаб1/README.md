## 1. Теоретическая база

Технология **Chroma Key** (цветовой ключ, рир-проекция, кеинг) представляет собой метод совмещения двух и более изображений или кадров видеоряда в единую композицию посредством замены однородной фоновой области заданного цвета на другое изображение.

### Математическая модель алгоритма

Пусть заданы:

- Изображение переднего плана: $I_{\text{fg}}(x, y) = (R_{\text{fg}}, G_{\text{fg}}, B_{\text{fg}})$, где $(x, y) \in [0, W-1] \times [0, H-1]$;
- Изображение заднего плана (фона): $I_{\text{bg}}(x, y) = (R_{\text{bg}}, G_{\text{bg}}, B_{\text{bg}})$;
- Целевой цвет фона: $C_{\text{target}} = (R_t, G_t, B_t)$;
- Допустимый интервал отклонения (порог / tolerance): $\Delta = (\Delta_R, \Delta_G, \Delta_B)$, либо скалярный допуск $\tau$.

Для каждого пикселя $(x, y)$ вычисляется бинарная маска принадлежности к цвету фона $M(x, y) \in \{0, 1\}$:

$$
M(x, y) = 
\begin{cases}
1, & \text{если } |R_{\text{fg}}(x,y) - R_t| \le \tau \;\land\; |G_{\text{fg}}(x,y) - G_t| \le \tau \;\land\; |B_{\text{fg}}(x,y) - B_t| \le \tau \\
0, & \text{иначе}
\end{cases}
$$

Для формирования итогового составного изображения $I_{\text{out}}(x, y)$ применяется операция попиксельного наложения:

$$
I_{\text{out}}(x, y) = M(x, y) \cdot I_{\text{bg}}(x, y) + (1 - M(x, y)) \cdot I_{\text{fg}}(x, y)
$$

Таким образом, пиксели переднего плана, попадающие в заданный цветовой интервал, замещаются соответствующими пикселями фонового изображения, а остальные пиксели сохраняют исходные значения.

## 2. Описание разработанной системы

Программная система реализована на языке Python и состоит из трех основных функциональных блоков:

1. **Библиотечная реализация (`chroma_key_lib`)**:

   - Использует библиотеку компьютерного зрения **OpenCV** (`cv2`).
   - Изображение загружается в виде NumPy-массивов формата BGR.
   - Построение диапазона интервалов:
     $$
     \text{lower} = \max(0, C_t - \tau), \quad \text{upper} = \min(255, C_t + \tau)
     $$
   - Формирование бинарной маски с использованием аппаратно-оптимизированной C++ функции `cv2.inRange(fg, lower, upper)`.
   - Инверсия маски через `cv2.bitwise_not(mask)`.
   - Побитовое логическое разделение и комбинирование переднего и заднего планов через `cv2.bitwise_and` и последующее сложение `cv2.add`.
2. **Нативная реализация (`chroma_key_native`)**:

   - Реализует алгоритм на чистом Python без использования готовых функций маскирования, цветовой фильтрации и наложения.
   - Загрузка пиксельных данных через структуру доступа `Image.load()`.
   - Вложенный цикл по строкам и столбцам матрицы изображения ($y \in [0, H)$, $x \in [0, W)$).
   - Вычисление абсолютного отклонения для каждого цветового канала пикселя в соответствии с математической формулой.
   - Прямая запись результирующего пикселя в буфер выходного изображения.
3. **Блок тестирования и бенчмаркинга (`run_benchmarks` и `main`)**:

   - Поддерживает как запуск через аргументы командной строки с произвольными параметрами, так и запуск без параметров с использованием тестовых изображений по умолчанию.
   - Проводит серию замеров времени выполнения на 6 разрешениях (от 200x150 до 2560x1440 пикселей) с помощью прецизионного таймера `time.perf_counter()`.
   - Генерирует сравнительный график производительности `benchmark.png` с помощью библиотеки `matplotlib`.

### 3.4 Выявленные закономерности

1. **Асимптотическая сложность**:
   Оба алгоритма имеют строго линейную сложность $O(W \times H) = O(N)$ относительно числа пикселей $N$. Например, при переходе от HD (0.92 млн пикселей) к Full HD (2.07 млн пикселей, рост в ~2.25 раза) время выполнения нативного варианта увеличивается пропорционально.
2. **Накладные расходы интерпретатора на малых размерах**:
   На малых разрешениях (200x150) время работы библиотечного варианта сопоставимо с нативным из-за фиксированных накладных расходов на вызовы C-API функций OpenCV и инициализацию структур данных.
3. **Преимущество векторизации и C++ на высоких разрешениях**:
   Начиная с HD-разрешений (1280x720, 1920x1080, 2560x1440) библиотечная реализация демонстрирует превосходство в **11–17 раз** (OpenCV обрабатывает 2K QHD всего за 0.128 секунды против 1.88 секунды в цикле Python). Это обусловлено SIMD-оптимизацией машинного кода в OpenCV и отсутствием динамической типизации для каждого из миллионов пикселей.

## 4. Выводы по работе

1. В ходе выполнения лабораторной работы был изучен и реализован алгоритм цветового ключа (Chroma Key) для замены заднего плана на основе анализа цветовых каналов и порогового интервала.
2. Алгоритм был реализован в двух вариантах:
   - Библиотечный с использованием встроенных функций OpenCV (`cv2.inRange`, битовые операции, `cv2.add`);
   - Нативный на чистом Python с явным обходом матрицы пикселей.
3. Проведено экспериментальное сравнение времени работы на различных разрешениях. Подтверждено, что библиотечная реализация масштабируется значительно эффективнее нативных циклов Python благодаря низкоуровневой оптимизации и отсутствию интерпретации каждой операции над пикселем.
4. Полученные изображения подтвердили корректность математической модели и эквивалентность результатов обоих методов.
